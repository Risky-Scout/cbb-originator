## Point-in-time observations

The following endpoints expose `startDateRange` / `endDateRange` filters:
- `/games`
- `/games/media`
- `/games/teams`
- `/games/players`
- `/lines`
- `/lineups/team`
- `/stats/team/season`
- `/stats/team/shooting/season`
- `/stats/player/season`
- `/stats/player/shooting/season`

Important nuance: date-bounded aggregation is not the same as historical vendor-receipt timestamping. It prevents using games after the cutoff, but it does not prove when a corrected source record became available to CBBD.

## Important exact-schema findings

1. `GameInfo` contains `homeTeamEloStart`, `awayTeamEloStart`, `homeTeamEloEnd`, and `awayTeamEloEnd`. The **start** fields are potentially useful historical pregame Elo features and are preferable to using a finalized season-level Elo snapshot, subject to coverage validation.
2. `PlayInfo.onFloor[]` directly supplies `team`, `name`, and `id`; it does not include position.
3. `PlayInfo.participants[]` supplies only `name` and `id`. Generic actor roles such as rebounder/stealer/fouler are not a separate universal field.
4. `ShotInfo` directly supplies shooter, made/missed, range (`rim`, `jumper`, `three_pointer`, `free_throw`), assisted flag, assister, and nullable x/y location.
5. `PlayerSubsititution` is athlete-centric. It contains an athlete plus `subIn` and `subOut` states with opponent points, team points, seconds remaining, and period. It is not a one-row paired `player_in`/`player_out` transaction.
6. `LineupStats` is an aggregate five-player unit: athletes, `totalSeconds`, pace, offense/defense/net ratings, and rich team/opponent unit stats. It does not directly contain stint start/end clocks.
7. `GameLineInfo` contains provider, spread, total, home/away ML, opening spread and opening total. It does not contain timestamped line movement, spread/total side prices, or player props.
8. The named schema `Availability` is data-coverage availability, not player injury status.
9. Venue records contain ID/source ID/name/city/state/country, but not venue coordinates, timezone, or elevation.
10. The attached schema has no dedicated player injury feed, coach entity, referee entity, or sportsbook player-prop endpoint.

## Retrieval / access details that matter operationally

- `/games` and `/games/teams` return up to **3,000 games** per filtered request.
- `/games/players` returns up to **1,000 games** per filtered request.
- `/lines` returns up to **3,000 games** per filtered request.
- Bulk acquisition therefore must use deterministic date-range chunking and verify row/game counts; otherwise a broad request can truncate coverage.
- `/scoreboard` requires **Patreon Tier 1+**.
- `/stats/team/leaderboard` requires **Patreon Tier 2+**.

## External gaps after this verification

### Core / availability-layer external requirements
- timestamped player injury / availability history, recommended **2021-22 through 2025-26**, plus continuous **2026-27** capture
- known minutes restrictions and their timestamps
- our own ingestion receipt / processing timestamps
- production live revision / correction semantics if CBBD is not sufficient for low-latency deployment

### Benchmark-only or optional external data
- historical player-prop lines with both-side prices and timestamps: **P1 benchmark only; not required for model training**
- dense historical game-odds movement / side-price history: **P2 retrospective benchmark; not build-blocking**
- prospective standardized Odds API snapshots at **T-24h, T-6h, T-1h, T-10m**: **P1 benchmark, strongly recommended**
- venue geospatial/timezone/elevation enrichment if validated
- coach/referee data if later justified

**Market-isolation rule:** sportsbook lines and props are not inputs to the flagship pure-originator prediction path.
